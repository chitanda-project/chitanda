# Mihomo H3 写入截止时间补丁验收（2026-09-27）

## 范围

Mihomo Stable `v1.19.31`（`ab405bad`）与 Alpha（`f103639c`）均将 Chitanda SDK 使用的 `github.com/quic-go/quic-go@v0.61.0` 指向本仓库已验收的补丁源码。Mihomo 自身使用的 `github.com/metacubex/quic-go` 不受此替换影响。构建脚本在标准 quic-go 版本改变、已有其他 replace 或补丁标记缺失时拒绝继续。

## 验收结果

- 两分支注入后，`./config` 和 `./adapter/outbound` 的 Chitanda 定向测试及 Linux `-race` 均通过；测试还在编译期检查 HTTP/3 和 QUIC 的可取消 Datagram 写入 API。
- Stable、Alpha 的 Linux ARM64 二进制均构建成功；构建元数据确认标准 quic-go 解析到 `.chitanda-quic-go`。
- 测试机 `168.138.209.1` 上的 Mihomo 客户端通过 H3 连接 `170.9.59.149` 上的隔离 Xray 服务端。两个版本的 HTTP 请求均返回 200，SOCKS5 UDP 回显均为 100/100。
- 同一路径的 SOCKS5 UDP 定速发送、服务端 UDP sink 计数如下。每轮 10 秒、1200 字节负载；百分比是客户端发出数与 sink 收到数之差，并非公网链路丢包定位结论。

| 构建 | 速率 | 发出 | 收到 | 差额 |
| --- | ---: | ---: | ---: | ---: |
| Stable 未打补丁基线 | 20 Mbps | 20,835 | 20,168 | 3.20% |
| Alpha 补丁版 | 20 Mbps | 20,835 | 20,530 | 1.46% |
| Stable 未打补丁基线 | 50 Mbps | 52,084 | 49,514 | 4.93% |
| Stable 补丁版 | 50 Mbps | 52,084 | 51,127 | 1.84% |

当时的结论：写入截止时间补丁已经进入两种 Mihomo 构建及真实 H3 数据路径；该测试未见吞吐回退，但仍有约 1.5%–2% 的端到端 UDP 差额。以下后续对照定位了这部分差额的主要成因。

## 后续冷启动丢包排查与补丁

同一发包脚本、1200 字节负载、10 秒测试中，将 SOCKS UDP 关联在发送结束后继续保持 3 秒，50 Mbps 仍出现 `52,084 -> 51,119`，排除测试脚本提前关闭关联造成的尾包误差。随后用同一脚本走 Mihomo `DIRECT` 至客户端本机 UDP sink，测得 `52,085 -> 52,085`；走 H3 之前先发一个预热包并等待 1 秒，50 Mbps 测得 `52,084 + 1 -> 52,085`。因此缺口集中于首次 H3 UDP 关联建立期间，并非稳态持续丢包。Mihomo `packetSender` 的每会话队列原为 128 包，满后执行 `packet.Drop()`；扩大该队列是针对这一阶段的修复。

| Mihomo 测试构建 | 条件 | 发出 | 收到 | 差额 |
| --- | --- | ---: | ---: | ---: |
| Stable，128 槽 | 冷启动 50 Mbps，关联保持 3 秒 | 52,084 | 51,119 | 965（1.85%） |
| Stable，128 槽 | 预热后 50 Mbps，含 1 个预热包 | 52,085 | 52,085 | 0 |
| Stable，2048 槽 | 冷启动 50 Mbps | 52,084 | 52,083 | 1 |
| Stable，2048 槽 | 冷启动 100 Mbps | 104,167 | 104,048 | 119（0.11%） |
| Stable，2048 槽 | 预热后 100 Mbps，含 1 个预热包 | 104,168 | 104,157 | 11 |
| Stable，4096 槽 | 冷启动 100 Mbps，第一轮 | 104,167 | 104,167 | 0 |
| Stable，4096 槽 | 冷启动 100 Mbps，第二轮 | 104,167 | 104,164 | 3 |
| Alpha，4096 槽 | 冷启动 100 Mbps | 104,168 | 104,168 | 0 |

构建注入现在将 Mihomo 的 `senderCapacity` 从 128 提升到 4096，并在上游该行变化时失败，而不是静默失效。Stable、Alpha 注入后均通过 `./tunnel`、`./adapter/outbound`、`./config` 测试，定向 `-race` 测试也通过；Alpha 的真实 SOCKS5 UDP 回显为 100/100。队列本身的指针容量在 64 位平台约由每会话 1 KiB 增至 32 KiB；排队中的报文缓冲还会额外占用内存。此修复不改变 QUIC 的拥塞控制，也不能保证超出链路持续承载能力时零丢包。上述结果仅证明这两台机器、这些速率和时长下的端到端差额；它们尚不能证明游戏断联已解决。测试只使用隔离端口，未替换线上服务。
